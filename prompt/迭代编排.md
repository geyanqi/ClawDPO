# ClawDPO 迭代编排

你负责监控状态、调用命令和筛选数据，在当前 Codex session 内持续运行 ClawDPO。
重复的大型处理优先调用仓库 CLI；一次性查看和筛选可以使用 shell、`jq` 或短脚本。

开始时阅读 `docs/design.md` 和 `workflow/* --help`。从启动消息或已有 manifest
取得最大轮次、当前 Best Model、Prompt Pool、Test Set、两份机评 request template
和 runs 目录；只有缺少无法执行的参数时才询问用户。

把当前 Best Model 固定为一个 Base Stage 的 Base Model。一个 Base Stage 可以有
多次 Training Iteration；Candidate 未晋级时 Base Model 不变，只有 Candidate
晋级才成功结束当前 Base Stage。

## Codex 并发

凡是能按 task 或 prompt 组独立判断的 Codex 工作，都必须持续占满当前 session
可用的 subagent 槽位。一个 subagent 完成后立刻补入下一项，直到待办文件清空；
主线程只负责分发、校验和汇总，不串行代做。并发不能改变判断单位：每个 subagent
只处理一个完整 task，不能为了增加并发把同一 task 再拆开。

## 循环

1. 选择一个尚不存在的 `runs/iteration-NNN` 路径，由 `rollout` 命令创建；
   以当前 Base Stage 的 Base Model 作为 Behavior Policy。持续查看
   `<runs_dir>/report.md`。失败重试仍使用同一个 Base Model。
2. 用 `workflow/prepare_data.py prompts` 维护 Prompt Pool。第一版不带历史
   chosen；从第二版开始，再用 `workflow/prepare_data.py history` 汇总全部历史
   chosen，并用当前 policy 调用 `infra/inference/rescore.py` 重评分。
3. 依次调用 `workflow/run_iteration.py rollout` 和 `select`。每个 prompt 固定
   rollout 256 条，不能提前停止或修改采样配置。
4. 对 `high_fail` 数据运行两次 Codex-as-Critic：
   - 调用 `workflow/run_iteration.py branch-prepare <iteration-dir>` 生成
     `branch-localization-tasks.jsonl`。用
     `prompt/codex/错误分叉定位.md` 处理，每个 subagent 只接收一条 task，并按
     上述规则拉满并行度；主线程原样汇总为定位结果 JSONL。
   - 调用 `workflow/run_iteration.py branch-rollout <iteration-dir> <定位结果.jsonl>`。
     脚本先校验定位结果，再固定原分叉 token
     续写 16 次，并只选定一个替代 token、固定它续写 16 次，最后生成
     `branch-outcome-tasks.jsonl`。
   - 用 `prompt/codex/分叉结果评测.md` 处理 outcome tasks。每个 subagent 接收
     一个分叉点的两组匿名回复，每组 16 条；并行度拉满，但这 32 条不能拆给多个
     subagent。critic 分别判断事实性、任务完成情况和两组质量，主线程原样汇总。
   - 调用 `workflow/run_iteration.py branch-evaluate <iteration-dir> <评测结果.jsonl>`，
     生成 `evaluated-branches.jsonl` 和
     `verified-branch-points.jsonl`。任务文件为空时不启动 subagent，但仍使用
     空结果文件完成后续命令。
5. 用 `prompt/codex/训练对构造.md` 处理 `candidate-packets.jsonl`。每个
   subagent 接收一个 prompt 组的 rollouts 和历史 chosen，在组内同时复核事实性、
   比较候选质量并直接写出 Swift DPO draft pair；持续拉满可用 subagent 槽位。
6. 主线程汇总 subagent 输出并过滤 `skip=true`。存在 pair 就写入
   `draft-pairs.jsonl`，调用 `freeze` 和 `train`；零 pair 立即停止整个循环并报告，
   不训练、不评测、不拉新数据。训练完成后确认 manifest 已记录本轮 Base Model、
   Dataset Revision 和 Trained Model Path。
7. 分别用 `workflow/evaluate_test.py infer` 生成 Best/Candidate 的 Test Set
   回复，再用 `judge` 生成 `test-results.jsonl`，最后调用
   `workflow/run_iteration.py evaluate`。晋级只服从机评结果，Codex 不改判。
8. Candidate 未晋级时，依次执行：
   - 用 Base Model 和 Candidate Model 分别调用 `infra/inference/rescore.py`
     重评分本轮 `dataset.jsonl`，固定写入 `base-pair-scores.jsonl` 和
     `candidate-pair-scores.jsonl`。
   - 调用 `workflow/build_diagnosis_packet.py <iteration-dir>`。
   - 按 `prompt/codex/训练失败诊断.md` 分析 packet，把 JSON 结果写入临时文件，
     再调用 `workflow/run_iteration.py diagnose` 保存结论。
   先快速排除有直接证据的工程错误；没有工程错误时先分析数据，再分析训练动态。
9. 读取 `test-badcases.jsonl` 和 `prompt/训练数据检索.md`，写一个 `WHERE`
   正则并调用 `mine`。只把 `mined-train.csv` 交给
   `workflow/prepare_data.py prompts`，不得绕过 Test Set 过滤。
10. Candidate 晋级时，以它开启下一个 Base Stage；未晋级时，按诊断中的单一改动
   开始新的 Training Iteration，但 Base Model 保持不变。达到最大轮次、零 pair
   或命令失败时停止整个任务，且不能把未晋级的 Base Stage 写成成功。

## 硬规则

- 全部历史 prompt 每轮重新 rollout；全部历史 chosen 每轮重新评分并附带。
- chosen 必须事实可靠且明显更好；rejected 必须是当前 policy 的 High
  Likelihood 回复；Extreme Tail 不进 pair；拿不准就跳过。
- Candidate 只有在事实性失败数不增加且质量胜场更多时才替换 Best。
- Candidate 未晋级不代表当前 Base Stage 已完成；下一次训练仍必须从该 Base
  Model 开始，不能从失败 Candidate 继续训练。
- 每次完成训练都必须保留 `(Base Model, Dataset Revision, Trained Model Path)`
  三元组；Candidate 未晋级也不能删除。
- Test Set 原始样本永远不能进入 Prompt Pool 或训练集。
- 分叉定位和分叉结果精评只能由 Codex subagent 完成，不能用裸 GPT/API 请求
  替代；主线程只分发 task、汇总原始输出并调用脚本校验，不改写 critic 判断。
- 命令失败就停止并报告；不恢复未完成的 iteration。
- 不发布、不部署、不修改线上模型别名。

结束时首先列出全部 Training Triples，再报告最终 Best Model、每轮晋级结果和
剩余 Test badcase。
