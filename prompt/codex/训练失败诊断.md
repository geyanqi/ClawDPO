# Codex 训练失败诊断

你要分析一个没有通过 Test Set 晋级的 Candidate Model。输入是
`diagnosis-packet.json`；其中列出了完整 Training Triple、汇总指标、代表性样本和
全部本地证据文件路径。

Candidate 已经被机评拒绝，你不能改判。你的任务是解释失败原因，并为同一个
Base Model 的下一次 Training Iteration 选择一个可验证的单一改动。

## 分析顺序

1. 快速排除明确工程错误：核对 Base、Dataset、Candidate 路径，训练命令，数据
   覆盖关系，chosen/rejected 方向，以及日志中的报错、NaN 或异常梯度。只有存在
   直接证据时才判为 `pipeline_bug`。
2. 没有明确工程错误时，首先检查数据：
   - chosen 是否事实可靠并明显优于 rejected；
   - pair 是否只是风格差异或弱排序；
   - 某种 `pair_type`、主题、长度或固定话风是否过度集中；
   - Test 退步是否与 Dataset Revision 奖励的行为相符。
   必须查看完整 `pair-diagnostics.jsonl`，不能只看 packet 中的抽样。
3. 再检查训练动态：
   - Candidate 是否普遍提高
     `chosen_raw_mean_logprob - rejected_raw_mean_logprob`；
   - chosen 的绝对 raw mean token logprob 是否同时下降；
   - 是否主要依靠大幅压低 rejected 获得上述 raw margin；
   - 训练日志里的 loss、grad norm、logps、DPO reward margin 和 reward
     accuracy 是否支持上述判断。raw margin 是跨模型生成倾向的诊断信号，不能
     代替训练器自己的 DPO reward margin。
4. 只选择证据最强的一个主因。证据不足时使用
   `insufficient_evidence`，不要凭经验猜学习率。

## 下一次尝试

- Base Model 必须原样使用 packet 中的 Base Model，不能换成失败的 Candidate。
- `data_problem`：选择 `rebuild_dataset`，明确只改变哪一项筛选、配比或 pair。
- `training_problem`：选择 `retry_training`，每次只改变一个训练变量。可用变量是
  `DPO_LEARNING_RATE`、`DPO_BETA`、`DPO_NUM_TRAIN_EPOCHS` 或
  `DPO_RPO_ALPHA`。
- `pipeline_bug`：选择 `fix_pipeline`，修复并验证后才能重新训练。
- `insufficient_evidence`：选择 `collect_evidence`，说明缺少哪一个直接证据。

不要同时建议多项改动，不要删除失败的 Training Triple 或 Dataset Revision。

只输出一个 JSON 对象，不添加 Markdown：

```json
{
  "verdict": "pipeline_bug|data_problem|training_problem|insufficient_evidence",
  "summary": "一句话主结论",
  "evidence": ["直接证据 1", "直接证据 2"],
  "data_findings": ["数据结论；没有则为空数组"],
  "training_findings": ["训练动态结论；没有则为空数组"],
  "next_attempt": {
    "base_model": "原样复制 packet.training_triple.base_model",
    "action": "fix_pipeline|rebuild_dataset|retry_training|collect_evidence",
    "single_change": "下一次只改变的一件事"
  }
}
```
