# 项目动机

## 背景

线上模型每天都会积累新的业务对话，其中一部分会暴露幻觉、事实错误或回答质量不足。传统迭代需要人工反复拉数据、筛 badcase、组织训练样本、启动训练和比较模型，周期长，也很难持续执行。

ClawDPO 希望让 Codex 接管这套已有 SOP：通过 owner 提供的固定工具读取脱敏对话、运行廉价机器评测、精读值得训练的 session、准备偏好数据、启动训练，并在训练后判断新模型是否真的优于当前最佳版本。

## 核心判断

高价值 DPO 数据不能只看答案好坏，还要同时区分三个信号：

- **正确性**：是否出现幻觉、事实错误等底线问题。
- **回复质量**：在事实可靠的前提下，哪条回复回答得更好。
- **当前策略 likelihood**：模型现在多容易生成这条回复。

DPO 的目标是让更好的行为更容易出现、让较差的行为更难出现。因此 chosen 和 rejected 都必须是当前模型实际有机会生成的行为。完全脱离当前策略分布的“超级坏答案”即使很差，也不是有价值的 rejected。

## 为什么使用 DPO

完整在线 RL 更有想象空间，但 model-train-model 场景需要清晰、稳定的反馈。第一版选择 DPO，以成对偏好数据控制训练信号；同时每一版模型都重新 rollout Prompt Pool，根据当前模型的分布重新生成 pair，从而获得近似 on-policy 的效果。

这套循环类似异步 RL 的 actor–evaluator–learner：当前模型负责采样，机器评测与 Codex 负责反馈，DPO trainer 更新策略。但它不声称是完整 RL，因为 v1 没有多步环境轨迹、累计回报或策略梯度信用分配。

## 目标

- 持续从脱敏业务对话中发现值得训练的问题。
- 用当前模型的大规模 rollout 构造精炼、可学习的 Preference Pair。
- 每轮训练后比较 Candidate Model 与 Best Model，只保留明确提升。
- 保存每一版 prompt、rollout、pair、模型和评测证据，使迭代可追溯。
- 在最大迭代轮次内自动循环，未达到标准时继续针对 badcase 补充数据。

## 非目标

- 不负责模型发布、部署或修改线上 serving alias。
- v1 不训练多步 agent trajectory，也不处理工具 action 的副作用。
- 不要求每版模型都进行人工标注；机器评测负责快速反映趋势，Codex 负责更强的最终判断。
- 不把测试集样本直接加入训练；测试失败只能指导检索相似但独立的训练数据。
